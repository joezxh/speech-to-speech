# 设计语言

随着本应用成长，保持其视觉一致性的参考。在触碰 `style.css`、`index.html`，或 `main.js` 中任何构建 DOM 的代码之前，请先阅读它。这里的每一条规则都已经在代码库中生效——本文件解释*为什么*，以便改动能扩展这个系统，而不是偏离它。

---

## 核心主张：颜色属于声音

这是一个语音应用。房间里唯一应该有颜色的东西，就是正在说话的那个东西。因此：

- **球体（orb）承载饱和的颜色。** 它发光，且光芒的色相随对话状态变化。
- **其余一切都是单色**——一个精确的冷灰暗色画布。表面、边框、按钮、面板、转写文本：全部灰度。
- 唯一的例外是微小的*角色回声*（一个单词大小的单色标签、一个小图标），它们借用球体的状态色，使转写文本用与球体相同的颜色语言来阅读。它们是单词大小的强调，绝不是填充。
- **品牌 logo 保留自身颜色。** Hugging Face 标记（`#ffd21e`）和 Cerebras 标记（`#f15a29`）在身份署名和 about 面板中以品牌色渲染——这是经过所有者批准的、刻意的例外。它只适用于这两个 logo；不要把它推广到其他 chrome（界面元素）。

如果你发现自己要在球体之外的任何地方添加有色背景、彩色边框或明亮按钮，请停手——那种颜色几乎肯定属于球体，或者根本不该存在。

## 颜色令牌（Color tokens）

全部定义在 `style.css` 的 `:root` 中。使用变量，绝不要在规则中写原始十六进制。

### 画布（单色世界）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#0a0b10` | 页面背景（接近黑的冷色） |
| `--bg-elev` | `#13151c` | 抬升的表面：气泡、面板、图标按钮 |
| `--bg-elev-2` | `#1b1e29` | 表面上的表面：历史正文、输入框 |
| `--border` | `rgba(255,255,255,.08)` | 默认细线 |
| `--border-strong` | `rgba(255,255,255,.16)` | 强调的细线 |
| `--text` | `#f5f6fa` | 主要文本；也是*主按钮*的填充 |
| `--text-dim` | `rgba(245,246,250,.65)` | 次要文本 |
| `--text-faint` | `rgba(245,246,250,.42)` | 说明、标签、页脚 |

### 声音（唯一的饱和色相）

这些是球体的状态颜色。它们出现在球体上，以及转写文本中作为小的角色回声——别处都没有。

| 令牌 | 值 | 含义 |
|---|---|---|
| `--accent` / `--speaking` | `#8b7dff` 紫罗兰 | 助手正在说话 |
| `--accent-2` / `--listening` | `#22d3ee` 青色 | 你 / 正在聆听 |
| `--processing` | `#f59e0b` 琥珀 | 思考 / 工具调用 |
| `--error` | `#ff6a75` | 错误 |
| `--success` | `#34d399` | 就绪 / 已连接 |

### 角色回声（语义别名——在聊天代码中使用这些）

| 令牌 | 映射到 | 出现位置 |
|---|---|---|
| `--voice-user` | 青色 | `YOU` 标签 + 用户气泡强调 |
| `--voice-assistant` | 紫罗兰 | `ASSISTANT` 标签 + 助手强调 |
| `--voice-tool` | 琥珀 | `TOOL CALL` 标签、扳手图标 |

**为何这样映射**：它精确镜像球体——当*你*说话时球体是青色（`state-listening`），当*助手*说话时是紫罗兰（`state-ai-speaking`），当它工作时是琥珀（`state-processing`）。转写文本是球体颜色故事的安静重放。

### 球体状态 → 光芒（`.circle.state-*` → `--glow`）

| 状态 | 光芒 |
|---|---|
| `signed-out` | 紫罗兰 `#8b7dff` |
| `authenticated` / `ready` | 绿色 `#34d399` |
| `connecting` / `connected` / `starting` | 黄色 `#facc15` |
| `listening` / `user-speaking` | 青色（`--listening`） |
| `processing` | 琥珀（`--processing`） |
| `ai-speaking` | 紫罗兰（`--speaking`） |
| `error` | 红色（`--error`） |

要新增一个状态？给它一个 `--glow`，如果它出现在转写文本中，就添加一个匹配的 `--voice-*` 别名，而不是一次性颜色。

## 字体排印（Typography）

两面字体，两个职责。绝不要引入第三面。

- **Inter**——正文和 UI。Wordmark、按钮、输入框、面板标题、散文、历史消息正文。主力；它应当感觉中立，不妨碍阅读。
- **Geist Mono**（`--font-mono`）——**机器之声**。保留给系统发出或它报告的标识符，绝不要用于人类散文。

### 何时用等宽（mono）是正确的

等宽表示"这是机器在说话或命名自身"。用于：

- 球体的状态说明（`.circle-caption`）
- 角色眉标（`YOU` / `ASSISTANT` / `TOOL CALL`）
- 工具调用名称和参数 JSON
- `·WebSocket` 传输标签、码率读数、连接标识符
- 空状态标签

等宽文本以大写呈现，`letter-spacing: ~0.1–0.14em`，字重 `500`，因此它读起来像一行打出的状态，而非标题。正文副本、按钮标签和说明性的 `small` 文本保持 **Inter**——把散文放进等宽会破坏这个隐喻。

字体在 `index.html` 中加载；如果 CDN 被屏蔽，字栈会优雅地回退到系统等宽字体。

## 布局（Layout）

- **一块连续的画布。** 顶栏下方或页脚上方没有分隔线，没有与内容竞争的面板 chrome。顶栏和页脚漂浮在舞台之上。保持这样——新章节只有在确实需要将它分离时，才配得上一根细线（`--border`）。
- **球体是主角和重心。** 它位于舞台的正中央。控件环绕它（麦克风 / 停止），说明文字在它下方。不要挤占它。
- **细线，而非盒子。** 分离来自 8–16% 白色的 `1px` 边框，以及间距，而不是来自厚重的填充或阴影。阴影柔和且低（`0 4px 18px rgba(0,0,0,.32)`），只用于抬升浮动元素（气泡、面板、模态）。
- **圆角：** `--radius-sm: 8px`（按钮、输入框、chip），`--radius-md: 14px`（气泡、消息正文、模态），`--radius-lg: 22px`（保留）。按元素大小选择；不要发明新值。
- **转写文本的两个阅读表面：** 右上角会记录并淡出的短暂气泡（仅桌面），以及一个滑入的历史面板供回顾。在手机上，气泡流被丢弃，面板变为全屏——在那里面板是唯一的真相来源。

## 组件（Components）

- **按钮。** 默认（`.btn`）是一个中性的抬升表面。*主*按钮是**近白色在暗色上**（`--text` 填充，`--bg` 文本）——页面上除了球体之外对比度最高的东西。没有彩色按钮；强调来自对比，而非色相。
- **图标按钮**（`.icon-btn`）为 `36px`、抬升表面、暗色图标在悬停时变亮。侧边控件（`.side-btn`）为圆形，在会话未激活前坍缩为零尺寸（桌面上按宽度，在移动端列中按高度）。
- **聊天气泡和历史消息**共享一个中性表面。它们通过**位置**（你 = 左，助手 = 右）加上**等宽角色标签**（角色回声色相）来区分——而非着色的填充。工具条目使用扳手图标 + 等宽 + 琥珀，位于同一个中性表面上。
- **徽章**（新消息圆点）是单色白色——一个信号，而非颜色强调。
- **焦点**是可见且中性的：输入框聚焦到 `--text-dim`；球体使用 `--glow` 着色的轮廓（它是球体，所以允许颜色）。

## 动效（Motion）

- **球体是音频驱动的，而非计时器驱动的。** 麦克风 RMS（`--audio-level`）和助手输出电平（`--ai-audio-level`）按显示帧率驱动缩放 / 不透明度，因此每个音节都让它移动。这是标志性的动画——让新动效从属于它。
- **默认安静。** 呼吸 / 发光的搏动是缓慢的（1.4–2.4s）且低对比度的。抵制添加零散的微动画；一个编排好的时刻胜过许多小的，过多的动效读起来像 AI 生成的。
- **首帧是冻结的。** `body.booting` 禁用所有过渡，直到第一帧提交（在 `main.js` 中一个 rAF 后被剥离）。任何会因此在加载时动画进入的新东西，都必须尊重这一点。
- 为你添加的任何动效，遵守 `prefers-reduced-motion`。

## 文案 / 写作声音（Writing / copy voice）

- 句子首字母大写（sentence case），平实的动词，没有填充词。经过调校且安静——匹配极简的画布。
- 按用户所控制的东西命名，而非按系统的内部命名。按钮准确说出它的作用，并在整个流程中保持同一个词。
- **空状态邀请行动**（"点击球体并开始说话"），它们不只是营造一种氛围。
- **错误说明发生了什么以及如何恢复**，用界面的声音——它们不道歉，也绝不模糊。
- 等宽标签是简洁的标识符（`YOU`、`TOOL CALL`）；散文保持在 Inter 中。

---

## 响应式底线（不可妥协）

每次改动都必须满足这些：

- 可下探到 `360px` 宽的手机。`@media (max-width: 600px)` 块已经处理了手机布局——扩展它，不要对抗它。
- 每个可交互元素都有可见的键盘焦点。
- 遵守 `prefers-reduced-motion`。
- 点击目标 ≥ `44px`；任何可点击的东西都有 `touch-action: manipulation`。

## 发布前——镜像检查（the mirror check）

1. 每种饱和颜色要么在球体上，要么是一个单词大小的角色回声？如果一个填充或边框是彩色的，移除那个配饰。
2. 等宽是否只用于机器 / 系统文本，而 Inter 用于一切人类内容？
3. 任何新状态是否同时有一个 `--glow` 和（如果它出现在聊天中）一个 `--voice-*` 别名？
4. 分离是细线 + 间距，而非盒子与厚重阴影？
5. 你添加了动效吗？它是否比球体更安静，且是 reduced-motion 安全的？
6. 移除一个配饰。极简外观依靠精确存活，而非添加。
