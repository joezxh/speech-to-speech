模块按职责分为四层：
- 入口层：`cli.py` 通过 `argparse` 分发 `serve` / `talk` / `local` 三个子命令，支持遗留的 `--mode` 参数；`__init__.py` 仅暴露包版本。
- 配置层：`config.py` 定义 `ConfigDocument` / `ResolvedConfig` / `ResolvedPipeline` / `ResolvedStage` 等不可变数据类，`load_config` → `validate_config` → `resolve_config` 三阶段把 YAML 文档校验为带来源标记 (`file` / `environment` / `default`) 的设置，并通过 `_metadata()` 延迟导入 `arguments_classes` 和后端注册表以隔离启动成本；`_config_yaml.py` 负责受控的 YAML 读取。
- 后端注册层：`backend_registry.py` 集中声明 `STT_BACKENDS` / `LLM_BACKENDS` / `TTS_BACKENDS` 三个 `BackendSpec` 列表，由 `build_backend_registry` 去重校验；`HandlerContext` + `create_backend_handler` 统一注入队列、`CancelScope`、`SpeculativeTurnTracker` 等运行时上下文，并通过 `_simple_handler_factory` / `_create_streaming_stt` / `_create_local_llm` 等工厂构造具体 handler，可选依赖缺失时包装为 `ImportError` 提示 `pip install "speech-to-speech[extra]"`。
- 运行期层：`s2s_pipeline.py` 基于 `HfArgumentParser` 解析命令行或 JSON，组装 `ParsedArguments`，在 `_build_handlers` 中串联 VAD→STT/AudioInput→LM→TTS 处理器链，并由 `_build_pipeline_unit` 产出 `PipelineUnit`；`configured_runtime.py` 的 `ConfiguredRuntime` 用 `Event` + `Thread` 管理多 pipeline 池、RealtimeServer 与可选 loopback 客户端的生命周期，`run_configured_command` 接管 SIGINT/SIGTERM 保证资源清理。
依赖方向单向：CLI → configured_runtime → s2s_pipeline → backend_registry → arguments_classes；YAML 解析不反向依赖运行时。
